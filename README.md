# gaknui-checker

学マスのぬいぐるみかどうかを判定できるアプリケーション

## 構成

```
.
├── data/
│   ├── raw/            # スクレイピングしたままの生データ
│   └── processed/      # リサイズ・正規化済みの学習用データ
├── scripts/            # 実行用スクリプト
├── notebooks/          # 学習の試行錯誤（Jupyter Notebook / Colab）
│   └── training.ipynb  
├── docs/               # 実装過程で整理した設計判断・理解度メモ
│   └── transfer-learning-notes.md
├── models/             # 学習済みモデルの保存先（.h5, .tflite, .json等）
└── web/                # フロントエンド（React / Next.js等）
    ├── public/models/  # ブラウザからロードするモデル配置先
    └── src/            # Webアプリのソースコード
```

## 構想

1. 学習用データをスクレイピングして集める

学マスのぬいぐるみの画像データはインターネットに無限にあるので学習データとして拾ってくる

2. モデル学習

ぬいの種類を判定できる機械学習モデルをつくる

3. web フロントエンド

フロントエンド上に乗るくらいにモデルを軽量化してデバイス上でモデルが動くようにする。カメラと連動できると◎

4. モデルの継続的学習

ユーザーからのフィードバックを集めて、モデルを改善していくデータパイプラインを構築する。

商業的にはユーザーの同意を得る必要がありそう。

## 学習について

画像の下処理（破損データの除去とリサイズ）は学習前に終わらせておく（学習に組み込む意味はないし画像のサイズも圧縮できるので）。
画像の拡張は学習時に行うことでストレージの節約をする。

### 画像の下処理

[Pillow](https://pypi.org/project/pillow/)が定番なので採用。

jpgとして開けない画像を除いたり、画像サイズを統一する。

### 転移学習

フルスクラッチでモデルを作ることはせず、転移学習で既存のモデルを自分のユースケースに特化させる。

理由
* MNISTのデータセットを使って同じことをしたことがあるから
* より実務に近いことをしたいから。色んな汎用が発達した今、こういうユースケースで一からモデルを構築することは少ないと思うから

### ベースモデル

[MobileNetV3 Large](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.mobilenet_v3_large.html)：モバイル上で動かすことを想定したときに定番のやつ。
